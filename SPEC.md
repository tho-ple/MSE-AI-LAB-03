# Specification: concurrent Python dependency intelligence

Version: 1.0

Status: Approved lab contract

Change policy: record interpretations in `DECISIONS.md`; do not edit this file
during implementation.

## 1. Objective

Given one or more exact PyPI package coordinates, aggregate independent package,
vulnerability, and supply-chain facts into one stable report. The service must
remain useful during a partial upstream outage, bound concurrency and memory,
and reuse only trustworthy complete assessments.

The application service is reused by:

- `POST /v1/scans`, an HTTP API accepting explicit coordinates; and
- `scan_project_dependencies`, an agent tool reading an allow-listed
  `requirements.lock` below a trusted workspace root.

## 2. Terminology and result semantics

- A **coordinate** is one normalized PyPI name and one exact PEP 440 version.
- A **source answer** is either validated domain data or one attributed failure.
- `[]` means a source answered successfully with no items.
- `null` means that source did not produce trustworthy data.
- A package result is **complete** only when all three sources succeeded.
- A project report is `complete` when every package result is complete,
  `partial` when any useful data exists but at least one result is incomplete,
  and `failed` when no source produced useful data for any requested package.

## 3. Inputs

### 3.1 HTTP input

`POST /v1/scans` accepts:

```json
{
  "dependencies": [
    {"name": "fastapi", "version": "0.115.0", "ecosystem": "PyPI"}
  ]
}
```

Requirements:

- 1–200 dependencies;
- only the `PyPI` ecosystem;
- valid normalized Python package names;
- exact PEP 440 versions; and
- one coordinate per normalized package name.

Invalid input returns HTTP 422 and performs no upstream work.

### 3.2 Agent-tool input

The tool accepts one workspace-relative path whose filename is
`requirements.lock`. Each logical line must be `name==exact-version`; blank
lines and comments are allowed. URLs, markers, extras, wildcards, duplicate
normalized names, invalid UTF-8, hidden/parent components, absolute paths, and
symlinks escaping the workspace are rejected.

The manifest is limited to 64,000 bytes and 200 dependencies. The tool never
writes to the scanned workspace.

## 4. Source contracts

### 4.1 PyPI

Call `GET /pypi/{normalized-name}/json`. Return:

- latest exact version; and
- `requires_python`, which may be absent.

Malformed or unparseable versions are invalid responses, not successful unknown
values.

### 4.2 OSV

Call `POST /v1/query` with the exact coordinate. Return a tuple of advisories.
An omitted `vulns` field is a successful empty answer. Merge records connected
through identifier aliases, including transitive alias chains, and select a
deterministic representative without discarding aliases or an available summary.

### 4.3 deps.dev

Call both version metadata and `:dependencies` endpoints. These two requests are
independent and must overlap. Return:

- reported licenses;
- publication timestamp when present; and
- count of nodes whose relation is `DIRECT`.

A graph must contain exactly one `SELF` root and no reported graph or node
errors. Missing repeated protobuf-style fields may represent valid empty lists;
missing required structure is an invalid response.

## 5. Concurrency and cancellation

- Start the PyPI, OSV, and deps.dev source operations for one package without
  waiting for one another.
- Scan different packages concurrently with a configurable positive package
  limit; the supplied default is 8.
- Preserve input order in the final report regardless of completion order.
- The shared HTTP pool remains bounded by configuration.
- Cancellation of a scan cancels and awaits its outstanding child tasks.
- Concurrent misses for the same coordinate share one in-flight load. Cancelling
  one waiter must not cancel work still required by another waiter; when the
  final waiter leaves, outstanding source work is cancelled.

## 6. Cache policy

Use a concurrency-safe, process-local TTL cache with:

- a monotonic clock;
- configurable positive TTL and maximum entry count;
- LRU eviction when capacity is exceeded;
- expiry fixed at insertion rather than refreshed by reads; and
- a key containing ecosystem, normalized name, and exact version.

Cache only complete assessments. A partial or failed result must call its
missing source again on the next scan. Report `miss`, `hit`, or `coalesced` for
each package result.

## 7. Failure behavior

Map source failures to one of:

- `not_found`;
- `timeout`;
- `rate_limited`;
- `unavailable`;
- `invalid_response`; or
- `unexpected`.

Every failure names its source, retryability, safe detail, and upstream status
when available. Never include upstream response bodies or credentials.

The supplied HTTP policy performs at most two attempts, retries timeouts,
transport errors, 429, and selected 5xx responses, honors a bounded numeric
`Retry-After`, streams a maximum one-megabyte identity-encoded body, and rejects
invalid JSON.

One failed source produces a partial package assessment containing the other
successful fields. If all sources fail for the whole request, the API returns
HTTP 503. A total scan deadline returns HTTP 504 and cancels the scan. Complete
and partial reports return HTTP 200.

## 8. Stable output

The report contains:

- project `status`;
- summary counts for total, vulnerable, outdated, and source failures;
- one ordered dependency record with installed/latest version, update status,
  Python requirement, licenses, direct-dependency count, publication time,
  vulnerabilities, cache status, completeness, and local failures; and
- a flattened top-level failure list.

`vulnerable_dependencies` counts packages with at least one observed advisory.
It is not a statement that packages with missing OSV data are safe.

## 9. Acceptance criteria

### AC-01 — validated coordinates

HTTP and manifest inputs accept valid exact PyPI coordinates and reject invalid
names, versions, duplicate normalized package names, and unsupported syntax
before upstream work.

### AC-02 — real source adapters

Fixture-shaped PyPI, OSV, and deps.dev responses become the specified domain
records. Malformed-but-valid JSON becomes an attributed `invalid_response`.

### AC-03 — source concurrency

All three source operations for one uncached package start before any is allowed
to finish. The two deps.dev endpoint calls also overlap.

### AC-04 — bounded package concurrency and order

No more than the configured package count runs at once, and the returned package
order equals the requested order.

### AC-05 — cache and single-flight

A second identical scan in the same API process reports hits and causes no new
upstream calls. Simultaneous identical misses perform one source load and report
one miss plus coalesced waiters. Expired and evicted entries reload.

### AC-06 — partial failure

When OSV returns 503 while the other sources succeed, the API returns HTTP 200,
status `partial`, useful metadata/supply-chain fields, `vulnerabilities: null`,
and one retryable OSV failure. The partial result is not cached.

### AC-07 — complete failure

When no source produces useful data, the API returns HTTP 503, status `failed`,
and all failures with correct source attribution.

### AC-08 — deadline and cancellation

A configured deadline returns HTTP 504 with code `scan_timeout`; outstanding
source operations observe cancellation.

### AC-09 — agent boundary

The tool produces the same report shape for a valid workspace manifest and
rejects absolute paths, parent/hidden components, other filenames, and escaping
symlinks without reading outside the workspace.

### AC-10 — engineering quality

Ruff lint/format, strict mypy, the complete deterministic test suite, and the
documented evidence checks pass. Production modules keep transport, parsing,
orchestration, caching, and presentation concerns separated.

## 10. Out of scope

- resolving transitive dependencies from an unlocked project;
- ecosystems other than PyPI;
- claiming that a zero advisory result proves safety;
- distributed cache consistency;
- authentication or public deployment of the lab API;
- a graphical frontend; and
- changing harnesses to compare output during implementation.
